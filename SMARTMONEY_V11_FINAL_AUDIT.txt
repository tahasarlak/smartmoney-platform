SMARTMONEY V11 — POSTGRESQL PHASE 2 AUDIT

Storage:
- V11 users, sessions, portfolios, broker accounts, paper orders, audit events and backtest history use SQLAlchemy/PostgreSQL.
- Market prices and watchlist use PostgreSQL.
- Signals and signal events use PostgreSQL.
- Private signals require a real v11_users row and are visible only to their owner through user-facing queries.
- Trusted live-price monitor can process both public and private signals.
- No SQLite imports or SQLite storage paths remain in backend/app Phase 2 repositories.

Migrations:
- backend/alembic.ini points to backend/migrations.
- backend/migrations/env.py loads DATABASE_URL or DIRECT_URL and imports all SQLAlchemy models.
- backend/migrations/versions/0001_initial_smartmoney_v11.py creates the initial metadata schema.
- Application startup does not create or drop schema.

GitHub Actions:
- Validates pooled and direct Neon secrets target the same PostgreSQL database.
- Optionally resets public schema only on manual dispatch with explicit RESET_PUBLIC_SCHEMA confirmation.
- Applies Alembic migrations.
- Runs the complete backend/tests suite.
- Verifies required tables, signal columns and Alembic revision.

Safety:
- Broker execution remains paper-only.
- Live trading remains disabled.
- The manual public-schema reset is destructive and must only be used while the database contains no required data.

Validation performed while preparing this bundle:
- Python compileall passed for backend/app and backend/tests.
- Full PostgreSQL test suite was not executed in this environment because Neon credentials are provided only through GitHub Actions secrets.
